# Gangolf production

Design: DiVoid #32404. This stack preserves the existing DiVoid/PostgreSQL dataset and named volumes. Docker commands target the configured daemon (`DOCKER_HOST=tcp://gangolf:2375`); env files and backup output are on the Docker client. No local path is assumed to exist on the remote host. No Compose plugin is needed.

Build the API from the `gangolf-api` directory using its Dockerfile; build ai-core from `ai-core`. Record immutable `sha256:` image IDs as `GANGOLF_API_IMAGE` and `GANGOLF_AI_CORE_IMAGE`. The checked-in stack pins the existing PostgreSQL17/pgvector, merged DiVoid PR236 and Processor images. Preserve these images for rollback.

Operations prepares a private directory (`GANGOLF_CONFIG_DIR`, mode0700), with mode0600 files `postgres.env`, `divoid.env`, `processor.env`, `api.env`, `ai-core.env`. These are Docker env-file data, not shell scripts. Never commit or print them. Set the following explicitly, preserving actual credentials and local graph IDs:

* postgres: `POSTGRES_DB=divoid`, `POSTGRES_USER=postgres`, `POSTGRES_PASSWORD` (existing bootstrap credentials).
* divoid: `Database__Type`, `Database__Host=divoid-processor-alpha-pg`, `Database__Port`, `Database__Instance`, `Database__User`, `Database__Password`, `DIVOID_KEY_PEPPER`, `Embedding__ModelPath=/data/models/embeddinggemma-2`. Use the qualified dedicated non-superuser app role; preserve the pepper.
* processor: `PROCESSOR_HTTP_ADDR=127.0.0.1:8080`, `PROCESSOR_WORKSPACE_DIR=/data/workspace`, `PROCESSOR_MODEL_URL=http://127.0.0.1:11434`, `PROCESSOR_MODEL_PROTOCOL=ollama`, `PROCESSOR_MODEL_ID=gemma4:latest`, local `PROCESSOR_DIVOID_URL` and `PROCESSOR_DIVOID_KEY`. Qualify the URL shape against the installed Processor.
* api: `GANGOLF_LISTEN=127.0.0.1:8092`, `GANGOLF_DIVOID_API_URL=http://127.0.0.1:8091/api`, `GANGOLF_DIVOID_TOKEN`, `GANGOLF_API_KEY_PEPPER`, local `GANGOLF_DIVOID_ROOT_ID`, `GANGOLF_DIVOID_MESSAGES_ID`, `GANGOLF_DIVOID_CONFIG_ID`, `GANGOLF_TWITCH_CREDENTIAL_DIR=/run/gangolf-credentials`.
* ai-core: `GANGOLF_API_URL=http://127.0.0.1:8092/api`, `GANGOLF_API_KEY`, canonical numeric `GANGOLF_TWITCH_BOT_USER_ID`, `GANGOLF_CHANNELS`, `PROCESSOR_URL=http://127.0.0.1:8080`, local `PROCESSOR_SUBJECT`, `PROCESSOR_CONFIG`, `PROCESSOR_MEMORY_CONFIG`. Preserve approved chat/memory policy semantics, gemma4:latest and thinking off.

Operations verifies port8092 is free, the local model is ready, all external named volumes/networks exist, and seeds `gangolf-production-twitch-secrets` through stdin. The volume root, mounted as `/run/gangolf-credentials`, must itself be owned by UID10001 with mode0700. Its `twitch-gangolf` entry must be a regular file owned by UID10001, mode0400, with link count1; avoid symlinks and hard links. Set both directory and file metadata while provisioning through the root helper, then mount the volume read-only in the API. A readable file inside a root-owned0755 directory fails the strict credential reader. A tmpfs populated only once loses credentials on restart. Never mount the workstation secret path on the remote daemon. Qualify both directory/file metadata and runtime credentialRef resolution as UID10001.

Run `python3 start.py`. It starts PG, waits readiness, then DiVoid, Processor and API in order. Existing containers are retained; adoption checks image, environment values, configured network, exact published port bindings, required named mounts and restart policy. Operations reconciles any mismatch. The script rejects definition mismatches and never deletes containers/volumes. Existing DiVoid container names and volumes are intentional. The approved existing LAN endpoint `http://gangolf:8091/api` is preserved: `:8091:80` declares Docker's empty HostIp/all-interface binding; health probes still use loopback. Adoption compares HostConfig.PortBindings exactly (HostIp empty, HostPort8091); Docker may expand this into IPv4/IPv6 addresses under NetworkSettings.Ports. This does not authorize extra service ports. For first adoption, operations preserves rollback containers before replacing any conflicting name. Restart policy is `unless-stopped`; Docker host restart does not guarantee dependency order, so application retry/restart and ordered readiness must be validated by operations.

Default startup leaves ai-core off. Only after observing the previous responder stopped, start with `GANGOLF_PREVIOUS_RESPONDER_STOPPED=yes python3 start.py --responder`. The API itself may connect IRC when configured, so operations must coordinate the single-responder window before API activation as well. Rollback stops new ai-core/API first, then restores preserved old runtime/config, retaining all graph writes and volumes. Never run two responders. This script does not disable Mamgo services.

## Backup and isolated restore

Set `GANGOLF_BACKUP_DIR` to a private directory on the client machine. `python3 backup.py` streams custom-format pg_dump, roles/globals, container metadata, protected config and the durable Twitch secret volume to a private staging directory. It publishes a checksummed backup only when every command succeeds, then retains seven completed copies. Failed staging directories remain private for diagnosis and do not trigger pruning. The remote Docker host to client copy is off-host relative to Gangolf; availability still depends on the client being online. Protect and encrypt the client filesystem/backup destination. Dumps/config archives contain secrets; never upload them to DiVoid or attach them to PRs.

Install `backup.py` at `~/.local/share/gangolf-production/backup.py`; install the two unit files under `~/.config/systemd/user/`. Create protected `~/.codex/secrets/gangolf-production/backup.env` with `DOCKER_HOST`, `GANGOLF_CONFIG_DIR`, `GANGOLF_BACKUP_DIR`, `GANGOLF_API_IMAGE`; then `systemctl --user daemon-reload` and `systemctl --user enable --now gangolf-backup.timer`. Verify timer and a successful first service run. This is daily logical backup, target RPO<=24h and seven copies, conditional on monitored client availability; it is not HA. For unattended operation ensure the user manager survives logout. Operations owns installation/activation.

Run `python3 restore.py BACKUP_DIRECTORY --name gangolf-restore-UNIQUE`. It verifies checksums, refuses existing targets and restores into a new isolated volume/container with no network or published port. It retains the result for operations' independent validation. A successful restore command is only a checkpoint: compare users/keys/nodes/relations/content, pgvector and app role privileges, start an isolated DiVoid with preserved pepper and authenticate both service identities; never restore over production for a test. Protected archives restore config/credentials separately under operator control. `backup.py` archives the secret volume as root with its `.` directory entry, preserving numeric owner and modes. Restore `twitch-secrets.tar` into a separate credential volume as root with permission/ownership preservation (`tar -xpf - -C /secrets` with archive on stdin), including the archived root-directory entry; do not recreate a root-owned0755 directory and copy only the file. Before mounting read-only, verify restored volume root UID10001/mode0700 and regular credential file UID10001/mode0400/link count1, then qualify the API reader. Take a fresh backup after correcting metadata; older archives can retain the earlier incorrect directory metadata. After validation, remove only that exact isolated container and volume. Take and qualify a backup before role/config/container replacement.

The currently qualified staging Processor uses loopback8093 and its distinct `gangolf-production-processor-workspace` volume while the previous Processor remains available on8080 for rollback. The default manifest represents canonical container `processor` at8080. Use `start.py --staging` and `materialize.py --staging` with a separate protected configuration directory for the qualified `gangolf-production-processor` at8093; canonical promotion requires operations to preserve the old processor, install the local configuration under the canonical name and qualify8080. Staging and canonical configurations must not be mixed. Pass `--chat-config` and `--memory-config` with locally qualified Processor policy IDs; node types must satisfy the installed Processor. Old unqualified IDs6/7 are not startup evidence. `materialize.py` snapshots the four selected service environments from Docker inspect and creates the fresh ai-core environment with the local IDs and endpoints; it never starts or modifies containers. Run it with the same Docker host, `GANGOLF_CONFIG_DIR`, and immutable image environment. It refuses to overwrite existing files. Treat that directory as protected credential/config storage, not documentation.
